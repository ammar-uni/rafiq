# تشغيل رفيق على خادم دائم

يستخدم النشر الأصلي Node.js 24 وsystemd. تعمل عملية واحدة باسم المستخدم المحدود `rafiq`، وتبدأ مع إقلاع الخادم. لا يلزم بقاء جهاز المشغّل أو سطح المكتب الرسومي مفتوحًا.

## فصل الملفات

- `/opt/rafiq/releases/<commit>`: نسخة البرنامج، بملكية root وللقراءة أثناء التشغيل.
- `/opt/rafiq/current`: رابط النسخة المستخدمة.
- `/etc/rafiq/rafiq.env`: بيانات اتصال ديسكورد ومفتاح التشفير، بملكية root وصلاحية 600؛ تقرؤها systemd وتسلّمها للعملية المحدودة.
- `/var/lib/rafiq/rafiq.enc`: التفضيلات المشفّرة، محفوظة خارج النسخ البرمجية.
- `/run/rafiq/status.json`: حالة الاتصال الحالية، وليست سجلّ بيانات المستخدمين.

لا تنسخ ملف الأسرار إلى GitHub. عند نقل نسخة قائمة انقل لقطة البيانات بمفتاحها نفسه والبرنامج متوقف. لا تستبدلها بمخزن فارغ.

## تحديثات GitHub

يفحص `rafiq-update.timer` فرع `main` في `ammar-uni/rafiq` كل خمس دقائق تقريبًا. لا يحتاج إلى رمز GitHub أو مفتاح SSH لدى GitHub: المستودع عام والخادم يسحب التحديث بنفسه.

يُقبل فقط معرّف النسخة الذي نجح أحدث تشغيل `push` لفحص `.github/workflows/check.yml` الخاص به. تُنزّل تلك النسخة بعينها، وتُرفض مسارات الأرشيف غير الآمنة، وتُثبت الاعتماديات من ملف القفل دون تشغيل install scripts. ثم تُشغّل فحوص رفيق بحساب بناء مستقل لا يستطيع قراءة أسرار البوت أو بياناته. يبقى البوت القديم متصلًا أثناء ذلك.

بعد نجاح الفحوص يوقف المثبّت البوت، ويبدّل رابط النسخة، ويسجّل الأوامر ثم يعيد التشغيل ويتحقق من اتصال Gateway ونبض العامل. إذا تعذر نجاح ذلك يرجع إلى النسخة السابقة. فحص الاتصال لا يحل محل تجربة الأزرار والتذكيرات في ديسكورد. إعادة التشغيل القصيرة تقطع متابعة المجالس الصوتية الجارية؛ لا يرسل البوت رسائل تعويضية عنها.

التفضيلات والمفتاح لا يُستبدلان عند التحديث. يحتفظ النظام بالنسخ البرمجية السابقة؛ لا ينشئ نسخ بيانات مستخدمين احتياطية. لا تنفذ ترحيلًا لا يمكن الرجوع عنه ضمن نشر آلي. يتطلب تغيير `deploy/schema-version` عن `2` مراجعة تشغيلية، وكذلك تغيير المثبّت نفسه أو وحدات systemd: تلك الملفات لا تحدّث نفسها بامتيازات root.

أخطاء التنزيل أو GitHub تُبقي النسخة الحالية تعمل. النسخة التي تفشل الاختبارات أو بدء التشغيل تتوقف محاولاتها الآلية حتى مراجعتها؛ تظهر النتيجة في سجل خدمة التحديث.

## أوامر الإدارة

```sh
systemctl status rafiq --no-pager
journalctl -u rafiq -n 30 --no-pager
systemctl list-timers rafiq-update.timer
journalctl -u rafiq-update -n 30 --no-pager
systemctl start rafiq-update.service
```

تشغيل المؤقّت يتطلب تثبيت `deploy/update.py` باسم `/usr/local/sbin/rafiq-update` ونسخ وحدات `deploy/` إلى `/etc/systemd/system/`، مع حسابَي `rafiq` و`rafiq-build` ومجلد بناء `/var/cache/rafiq-build`. النسخة الأصلية تحتاج إلى إعداد المشغّل مرة واحدة. لا تدّع تفعيل التحديث الآلي قبل التحقق من المؤقّت وتجربة تنزيل نسخة وفحصها.

يحمي المشرف من توقف العامل وانقطاع الاتصال. تعطل ملف الإعداد أو تلف البيانات يوقف التشغيل للمراجعة بدل تكرار المحاولة بلا نهاية. الاستضافة الدائمة لا تعني ضمان انعدام الانقطاع، ولا تغني عن متابعة الأخطاء أو تحديث Node.js ونظام التشغيل.
