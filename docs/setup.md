# إعداد رفيق وتجربته

## حساب البوت

1. أنشئ تطبيقًا في [Discord Developer Portal](https://discord.com/developers/applications) وسمّه رفيق.
2. انسخ Application ID من General Information إلى `DISCORD_APPLICATION_ID` في ملف `.env` المحلي.
3. من صفحة Bot، ضع الرمز في `DISCORD_TOKEN` محليًا. لا تضعه في رسالة أو مستودع. ارفع `assets/rafiq-avatar.png` لصورة الحساب إذا رغبت.
4. لا تفعّل Message Content أو Server Members أو Presence Intent. يستخدم البرنامج Guilds وGuild Voice States فقط.
5. ابدأ بسيرفر تجربة: فعّل Developer Mode في ديسكورد، وانسخ معرّف السيرفر إلى `DISCORD_GUILD_ID`.

## تشغيل محلي

```powershell
npm ci
npm run setup:local
```

يُعدّ `setup:local` الملف المحلي ويحفظ مفتاح تشفير جديدًا إن لم يوجد، دون تغيير بيانات الاعتماد الموجودة أو طباعة الأسرار. أكمل قيم حساب ديسكورد في `.env`، وانشر سياسة الخصوصية مع رابط الدعم ثم ضع `RAFIQ_PRIVACY_URL` و`RAFIQ_SUPPORT_URL`. ضع رابط السياسة العام نفسه في General Information في بوابة المطوّرين. لا يصلح رابط ملف داخل مستودع GitHub خاص.

نفّذ:

```powershell
npm run doctor
npm run invite
```

افتح رابط الدعوة الناتج من `invite`. يطلب البوت عرض القناة، وإرسال الرسائل، وإرفاق الملفات، وقراءة تاريخ الرسائل لتحديث بطاقته. لا يطلب Administrator أو إدارة الرسائل أو الانضمام للصوت.

**بعد إتمام الإضافة إلى سيرفر التجربة**، سجّل الأوامر وشغّل البرنامج:

```powershell
npm run register
npm start
```

امنحه رؤية القنوات الصوتية المقصودة؛ احترام منع رؤية القناة جزء من سلوك ديسكورد. لا ينضم البوت للصوت ولا يستمع إليه. يظل الجهاز أو الخادم مشغّلًا ومتصلًا كي تعمل التذكيرات.

أوامر العضو:

- `/rafiq` لفتح مساحته، مع اختيار قسم اختياري.
- الأزرار والقوائم داخل بطاقته للتفعيل والمكتبة والمحفوظات والمؤقّت والإلغاء.

أوامر المشرف صاحب صلاحية Manage Server:

- `/rafiq-setup channel:...` لنشر بطاقة واحدة أو تحديث البطاقة السابقة. يمكن تثبيتها يدويًا. لتغيير القناة احذف البطاقة القديمة ثم أعد الأمر.
- `/rafiq-status` لعرض حالة إعداد السيرفر؛ لا يعرض سجل عبادات أو أسماء مشتركين.

تسجيل الأوامر يحدّث أوامر رفيق الثلاثة بأسمائها، ولا يمس أوامر أخرى في التطبيق. الأوامر المقيدة بسيرفر التجربة لا تظهر عالميًا في الخاص. عند الانتقال للتشغيل العام، اترك `DISCORD_GUILD_ID` فارغًا وأعد `npm run register`، ثم تحقق من التسجيل العام قبل إزالة تسجيلات أوامر التجربة المطابقة عبر واجهة Discord API؛ قد يستغرق ظهور الأوامر العامة بعض الوقت. أُنجز ذلك لتطبيق رفيق الرسمي؛ يكفي أصدقاء المشروع اتباع [دليل الإضافة](server-trial.md).

## تجربة أولى في ديسكورد

1. شغّل البوت وافتح `/rafiq`. يجب أن يظهر الرد لك وحدك، وألا يصلك شيء تلقائيًا قبل التفعيل.
2. فعّل تذكير المجلس من سيرفر التجربة، ثم اطلب «اختبر الخاص»؛ يحدّ التطبيق الاختبار بمرة في الدقيقة.
3. ادخل قناة صوتية مرئية للبوت مع شخص آخر لمدة ٥ دقائق أو أكثر، ثم اخرج وانتظر نحو ٤٥ ثانية. البداية رسالة خاصة صامتة واحدة.
4. في تجربة أخرى، عد خلال المهلة: ينبغي ألا تأتي رسالة وداع. تغيير القنوات وكتم الميكروفون لا يعدّان مغادرة.
5. جرّب إعداد التكرار، والمحفوظات، وإلغاء المؤقّت، وإيقاف التنبيهات. خيار الحذف يمحو سجلّك من قاعدة البوت بعد الضغط على تأكيده.

اختبارات `npm run check` ومحاكاة `npm run demo` تتم دون حساب ودون إرسال خارجي. لا تستبدل تجربة ديسكورد الفعلية الموضحة أعلاه.

## حفظ البيانات والتشغيل المستمر

شغّل **عملية واحدة** من رفيق لكل مخزن بيانات. تعمل SQLite في الذاكرة، وتُحفظ لقطة مشفّرة بـ AES-256-GCM في `data/rafiq.enc` عند تغيّر البيانات. لا تُكتب قاعدة SQLite أو ملفات WAL غير مشفّرة إلى القرص. يحمي `RAFIQ_DATA_KEY` اللقطة؛ فقدانه يعني تعذّر استعادة البيانات. اقصر الوصول إلى `.env` على المشغّل المصرّح له، واحفظ مفتاح الاستعادة منفصلًا عن أي نسخ للبيانات. استخدم قرصًا محميًا ومشفّرًا للمضيف أيضًا، بما فيه ملفات الذاكرة الافتراضية والنسخ الاحتياطية.

اجعل `data/` دائمًا إذا نقلت التشغيل إلى خادم، ولا تضعه على نظام ملفات شبكي. هذه آلية لسيرفرات قليلة بحد ملف ١٦ ميبيبايت، وليست تخزينًا لتشغيل موزّع. تنتهي جلسات الصوت الموجودة في الذاكرة مع توقف البوت؛ لا يرسل وداعًا متأخرًا عند الإقلاع. يبقى مؤقّت العضو في المخزن، لكنه يفوت دون إرسال إذا مضت أكثر من ٥ دقائق على موعده.

من الإصدار 0.5، يمنع ملف `.guard` فارغ فتح المخزن مرتين باستخدام قفل يوفره نظام التشغيل عبر SQLite. لا يحتوي الملف على بيانات أعضاء، ويتحرر القفل عند خروج العملية أو موتها. يبقى الملف الفارغ على القرص؛ **لا تحذفه أثناء التشغيل**. المفتاح الخاطئ أو الملف التالف يوقف الإقلاع دون الكتابة فوق البيانات.

**الترقية من 0.4:** أوقف النسخة القديمة أولًا وتحقق من توقف العملية. إذا بقي `data/rafiq.enc.lock`، تحقق أيضًا من توقف رقم العملية المكتوب فيه، ثم أزل ملف `.lock` القديم فقط. لا تحذف اللقطة المشفّرة، ولا تغيّر المفتاح. ترفض النسخة الجديدة التشغيل ما دام هذا القفل القديم موجودًا؛ صيغة البيانات المشفّرة لم تتغير.

`npm start` يشغّل مشرفًا وعامل بوت واحدًا. يعيد المشرف العامل المتعطل بعد ٥ ثوانٍ، ثم يضاعف المهلة حتى دقيقة؛ تعود المهلة الأساسية بعد ٥ دقائق من الاتصال المستقر. يعيد العامل إذا غاب نبضه أكثر من ٣٠ ثانية أو استمر انقطاعه أكثر من ٩٠ ثانية. عند طلب الإيقاف ينتظر العمليات الجارية مدة تصل إلى ٢٠ ثانية قبل إنهاء العامل المتعطل. Ctrl+C يوقف المشرف والعامل دون إعادة تشغيل مقصودة.

أخطاء المحتوى المراجع أو الإعدادات أو فتح المخزن توقف المشرف للمراجعة بدل تكرار المحاولة. سجّل التشغيل يحوي وقت الحدث ونوع الخطأ وحالة الاتصال، دون نصوص رسائل الأعضاء أو رموز الدخول. إذا فشل الإعداد شغّل `npm run doctor` لتحديد الحقول الناقصة محليًا.

شغّل `npm run health` من نافذة أخرى: نجاحه يعني نبضًا حديثًا واتصال Gateway جاهزًا؛ لا يثبت استجابة كل زر أو قابلية مراسلة كل عضو. يُحفظ ملف الحالة في `output/rafiq-status.json` افتراضيًا، ويمكن تغييره بـ `RAFIQ_STATUS_PATH`. لا تنشر هذا الملف، وشغّل مشرفًا واحدًا فقط لكل نسخة.

للمضيف الذي يوفر Docker: بعد إعداد `.env` يمكنك بناء وتشغيل `docker compose up -d --build` ومراجعة `docker compose logs --tail=30`. تستخدم الحزمة مستخدمًا غير إداري، وقرص بيانات دائمًا، ونظام ملفات للتطبيق للقراءة فقط. لا تحذف قرص `rafiq-data` عند التحديث. تحتاج النسخة القائمة إلى نقل اللقطة إلى القرص وضبط صلاحياتها قبل بدء الحاوية؛ لا تبدأ بمخزن فارغ على أنه ترحيل للبيانات. لا يشمل هذا الأمر شراء مضيف أو ضمان بقائه متصلًا. [خيارات الاستضافة وحدودها](hosting-options.md).

لا توجد نسخ احتياطية تلقائية. إذا احتجت نسخة يدوية، أوقف البرنامج أولًا وانسخ اللقطة المشفّرة فقط؛ لا تجمعها مع `.env` في الأرشيف نفسه. طبّق طلبات الحذف على النسخ القديمة أيضًا، ولا تستعد بيانات أو اشتراكات سبق حذفها. حذف بيانات البوت لا يحذف الرسائل الموجودة في حساب العضو في ديسكورد.

ملفات SQLite القديمة لا تُحوّل بمجرد إعادة تسميتها؛ يرفضها المخزن ويتركها دون تعديل. إذا كانت لديك بيانات تشغيل من إصدار سابق، يلزم ترحيل منفصل قبل التحديث. لم توجد بيانات تشغيل حقيقية في هذا المشروع عند إضافة التشفير.

راجع [مراجعة السياسات ومتطلبات الإطلاق](discord-policy-review.md) و[سياسة الخصوصية](privacy-policy.md)، وتابع مساحة الدعم للاستجابة إلى البلاغات وطلبات البيانات.

## عند تعذّر الإرسال

- إذا ظهرت `The application did not respond in time` عند الضغط على زر، فتحقّق أولًا من أن عملية البوت تعمل ومتّصلة. يحتاج ديسكورد ردًا أوليًا خلال ٣ ثوانٍ؛ لذلك لا تعمل البطاقة وحدها عندما يتوقف البرنامج. رفيق يؤكّد استلام الضغط قبل معالجة الطلب. [توثيق مهلة التفاعل](https://docs.discord.com/developers/interactions/receiving-and-responding#interaction-callback).
- تشغيل `npm start` يتابع العامل، لكنه لا يبقي المشرف نفسه حيًا بعد إغلاق جلسة مؤقتة أو إطفاء المضيف. استخدم خدمة تشغيل مناسبة للمضيف، مع مراقبة السجل وتشغيل نسخة واحدة فقط. إغلاق الجهاز أو دخوله في وضع السكون يقطع الاتصال. تسجيل الخروج من حساب المشغّل في متصفح ديسكورد لا يبطل رمز البوت ولا يغني عن تشغيله.
- افتح الرسائل الخاصة لأعضاء السيرفر، وتأكد من عدم حظر البوت، ثم استخدم «اختبر الخاص».
- عند خطأ ديسكورد الذي يعني عدم القدرة على مراسلة العضو، يعلّق رفيق المحاولات حتى ينجح الاختبار؛ لا يرسل بدلًا منها إلى القناة العامة.
- عند فشل شبكة مبهم، تُحتسب المحاولة ضمن السقف لمنع تكرار الرسالة، ولا تُعاد تلقائيًا.
- إذا لم تظهر الأوامر، تحقق من معرّف التطبيق ومعرّف سيرفر التجربة ومن إتمام التسجيل.
