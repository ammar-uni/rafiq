# نشر تنزيلات رفيق وتحديثها

تُخدم صفحة التطبيق من `https://rafiq.ammarbalkhi.com/#windows`. يبقى هذا الرابط ثابتًا، بينما يحمل كل مثبّت رقم إصداره في مساره.

## فصل الصفحة عن التطبيق

نسخ واجهة الموقع في `/opt/rafiq-website/releases/<release>/public/`، والرابط الجاري هو `/opt/rafiq-website/current`. بيانات الإصدار والمثبتات مستقلة تحت `/var/opt/rafiq-downloads/public/`؛ لذلك لا يستبدل نشر واجهة جديدة إصدار التطبيق.

يُستورد `/etc/opt/rafiq-downloads/routes.caddy` داخل كتلة موقع رفيق:

```caddyfile
import /etc/opt/rafiq-downloads/routes.caddy
```

يحجز هذا الاستيراد `/release.json` و`/downloads/*` فقط. حافظ عليه عند تحديث قالب Caddy، وافحص الإعداد قبل إعادة تحميل الخدمة. لا تحتاج هذه العملية إلى إعادة تشغيل البوت.

## بيانات الإصدار

تقرأ الصفحة `GET /release.json` من الأصل نفسه. الحقول هي:

- `available`: هل النسخة معتمدة للتنزيل؟
- `version`: إصدار رقمي بصيغة `X.Y.Z`.
- `url`: مسار مثل `/downloads/Rafiq-Setup-X.Y.Z.exe`.
- `sha256`: بصمة الملف المعتمد، ٦٤ خانة ست عشرية.
- `sizeBytes`: حجم الملف بالبايت؛ يجب أن يطابق استجابة `HEAD`.

عندما يكون التنزيل غير متاح تكون `available:false` وبقية الحقول `null`. يُرسل الخادم `Cache-Control:no-store` لبيانات الإصدار، و`no-store,no-transform` لملفات التنزيل، دون تغيير قواعد Cloudflare العامة.

ملف `release.json` غير المفعّل داخل حزمة الواجهة يبقى احتياطيًا للمعاينة؛ استيراد Caddy يخدم بيانات الإنتاج من المسار الدائم. لا تفعّل نسخة عامة بمجرد نشر تصميم الصفحة.

## نشر ملف معتمد

مصدر الأداة في `deploy/downloads/publish.py`، والرافع المحلي في `deploy/downloads/Publish-RafiqDownload.ps1`. لا تُخزّن عنوان المضيف أو بيانات الدخول في المستودع؛ مرّر المضيف الإداري المعتمد إلى المعامل `-Server`.

يحتاج الرافع إلى `-InstallerPath` و`-Version` و`-ExpectedSha256` و`-Server`. يرفع الملف إلى مجلد مرشحين خاص ويتحقق منه. **دون `-Publish` لا يتيح الملف للزوار.** بعد اعتماد الإطلاق العام، يفعّل `-Publish` الملف نفسه ويحدّث بيانات الإصدار ويتحقق من عنوان التنزيل وحجمه.

تقبل الأداة مثبّت المستخدم وحده باسم `Rafiq-Setup-X.Y.Z.exe`. تحقّق من اختبارات المثبّت والترقية وحفظ الإعدادات قبل اعتماد الملف. لا ترفع لوحة الإدارة أو مفاتيح التوقيع أو المسودات أو تقارير المستخدم. فحص البصمة وصيغة PE لا يمنح اعتمادًا للنشر ولا يعادل توقيع Windows.

لا يمكن استبدال محتوى رقم إصدار منشور بملف مختلف؛ استخدم رقمًا جديدًا. تُحفظ النسخة المعتمدة في أرشيف خاص تحت `/var/opt/rafiq-downloads/releases/<version>/`.

## الإدارة والرجوع

عبر الاتصال الإداري المعتمد:

```sh
rafiq-publish-download status
rafiq-publish-download activate --version X.Y.Z
rafiq-publish-download disable
```

يعيد `activate` نسخة منشورة سابقة بعد التحقق من الملف والبصمة. يوقف `disable` بيانات التنزيل ويزيل النسخ العامة مع حفظ الأرشيف الخاص. أي نسخة سبق تنزيلها تبقى لدى صاحبها؛ وقد تحتاج نسخ قديمة خُزّنت قبل سياسة عدم التخزين إلى مسح منفصل من Cloudflare.

نشر التطبيق لا يرسل إعلانًا إلى ديسكورد. إعلان الإطلاق وتحديث البطاقة عمليتان منفصلتان، بعد التحقق من النسخة والصفحة. لا تمس أداة التنزيل تفضيلات مستخدمي التطبيق أو مخزن البوت.

## التحقق

```sh
python3 -m unittest discover -s deploy -p 'test_*.py'
```

تغطي اختبارات التنزيل الملفات ذات البصمة الخاطئة، والمسارات والروابط الرمزية غير المسموحة، وثبات الإصدار المنشور، والرفع الخاص، والرجوع والإيقاف، وحفظ النسخة النشطة عند فشل تحديث البيانات. تستخدم الاختبارات ملفات PE صناعية ضمن مجلدات مؤقتة، ولا تشغّلها أو تنشرها.

تُحفظ تفاصيل المضيف والمسارات المحلية وتسليم الإصدار خارج مصادر النشر العامة.
